# Аудит базы и каркаса — октябрь 2026

Что проверяли, что нашли и что с этим сделали. Документ — рабочий журнал, а не
правила: правила живут в [CORE.md](./CORE.md), [AI-CONTRIBUTING.md](./AI-CONTRIBUTING.md)
и [DATA-QUALITY.md](./DATA-QUALITY.md).

## 1. Метод

Шли «от данных к коду», а не наоборот:

1. Собрали полный дамп шкалы (826 объектов: 544 авторских, 282 записи справочника
   на шкале, 487 в JSON, 30 слиты с карточками; 293 связи) и прочитали все даты
   по каждой линии глазами — год, месяц, день, `endYear`, страна, `approximate`.
2. Отдельно прогнали все 487 подписей дат справочника (`dateLabel`) через парсер
   скрипта импорта и сравнили с тем, что лежит в JSON, — чтобы отличить ошибки
   распознавания от ошибок самого импорта.
3. Прогнали заголовки записей через классификатор линий и сравнили с тем, где
   запись должна стоять по смыслу.
4. Сравнили авторские карточки между собой: длина `detail`, наличие `parallel`,
   источников, `url`.
5. Код смотрели только там, где данные показывали проблему, плюс обычный
   проход по контрактам: `npm run lint && npm test && npm run build` до и после.

Исходный OCR справочника (`reference-events-ocr.json`) в репозитории отсутствует,
поэтому JSON **не перегенерировали**: при перегенерации по восстановленному входу
поплыли бы id и дедупликация. Вместо этого ошибки исправлены наложением
(`src/data/referenceCorrections.ts`), а скрипт импорта починен, чтобы при появлении
исходника те же ошибки не воспроизвелись.

## 2. Каркас и код

Состояние хорошее: lint чистый, 83 теста зелёные, сборка проходит, контракты
(ссылки, localStorage, форматы файлов, границы чанков) охраняются тестами.
Три больших файла (`useTimelineState.ts`, `TimelineSection.tsx`, `PeopleBuilder.tsx`)
длинные, но линейные и покрыты e2e; дробить их ради размера не стали — это риск
без выгоды для читателя.

Единственное место, где код был причиной ошибок данных, — `scripts/import_history_reference.py`:

| Ошибка импорта | Пример | Было | Стало |
| --- | --- | --- | --- |
| Диапазон веков читался как один век | «IV – VII вв.» | `year: 300` | `301…700` |
| «Конец N в. до н. э.» считался в сторону роста | «Конец VII в. до н. э.» | −690 | −610 |
| Начало/конец тысячелетия до н. э. перепутаны | «Конец 4-го тыс. до н. э.» | −3900 | −3100 |
| Квалификатор только у первой границы | «V – начало VI в.» | 401 | `401…511` |
| Список диапазонов ломал годы | «1768 – 1774, 1787 – 1791 гг.» | `1768…1774` | `1768…1791` |
| Нормализация NFKD дробила «й» и «ё» | «Карибский кризис» → «карибскии» | маркеры не срабатывали | NFC |
| Короткие маркеры совпадали внутри слов | «нато» ⊂ «Эхнатона» | Эхнатон в «Мире» | граница слова |
| Классификатор видел обрезанный заголовок | «…Рапалльского договора меж-» | — | полный заголовок |

Плюс расширены таблицы маркеров линий (русская история, Чехия, Венгрия, Сербия,
Южная Африка, Османы, Дели, Сонгай и т. д.): на текущих данных классификатор
расходится с ручной разметкой в 6 записях из 487, и все шесть — слитые записи,
которых нет на шкале.

## 3. Данные

### 3.1. Авторские карточки (544)

Фактических ошибок в датах не нашли. Поправки:

- `approximate: true` у пяти условных дат: `ru-slavs-550`, `jp-yamato-400`,
  `jp-buddhism-538`, `by-rogneda-980`, `de-limes-260`.
- У 104 карточек добавлены месяц и/или день там, где дата события общепринята
  и однозначна (Грюнвальд уже был; добавлены Оршанская битва, Люблинская уния,
  Кревская уния, Клермонский собор, Босворт, Вестфальский мир, Код Наполеона,
  Цусима, Синьхайская революция и др.). До 1582 года — юлианские даты, как
  принято у историков; после — новый стиль. Процессам без чёткого дня
  (Отечественная война 1812 года, «Две Германии» 1949) намеренно оставлен год.
- Зафиксирована в [AI-CONTRIBUTING.md §6](./AI-CONTRIBUTING.md#6-даты-и-календари)
  конвенция «до 1582 — юлианская дата, после — григорианская», которой база
  фактически уже следовала.

### 3.2. Записи справочника (487 в JSON, 282 на шкале)

78 поправок в `referenceCorrections.ts`: 70 переносов между линиями и 18
исправлений дат (часть записей получила и то и другое).

- 24 события русской истории стояли в колонке «Мир» (Судебник 1497, Ливонская
  война, Северная война, Табель о рангах, Крымская война, Кровавое воскресенье,
  Московская и Курская битвы…). Причина — «петр i»/«русск…» не было в маркерах,
  а «московская» не содержит подстроки «москв».
- Египетская линия теряла Новое царство, Эхнатона и персидское завоевание;
  Александр Македонский стоял в Древнем Риме; халифат, Делийский султанат,
  Сонгай и монгольское государство — в «Мире».
- Диапазоны веков: Новое царство (XVI–XI вв. до н. э.) стояло в −1100 годе,
  Великое переселение народов — в 300-м, Навуходоносор II — в −690.
- «Апипур» — распознанное «Ашшур» (так и в описании записи): исправлен заголовок.

Намеренно не тронуты: «Семь чудес света» и «Экспансия Рима» (обзорные записи,
год условный по справочнику), Великоморавская держава (линии Моравии нет;
осталась в Чехии), Ялтинская конференция (мировое событие — «Мир»).

## 4. Ограничение этого прохода

Аудит выполнялся без доступа к сети за пределами GitHub/npm/PyPI. Поэтому:

- ни один внешний URL в этом проходе не открывался и ни один новый `url`
  не добавлен — по правилу [DATA-QUALITY.md](./DATA-QUALITY.md#что-такое-источник-без-url);
- все исправления дат опираются на даты, для которых расхождений между
  академическими справочниками нет (годы правлений, битв, договоров);
- расширение текстов и новые карточки с опорой на официальные государственные
  и архивные сайты — следующий проход, когда можно открыть каждую ссылку.

## 5. Как продолжать

1. Новые карточки — по списку белых пятен из §3.3, по одной линии за PR,
   с двумя источниками (из них хотя бы один — архив, музей или государственный
   сайт страны), текстами в `content/items/<страна>/<id>.md`.
2. `parallel` у 120 карточек без него — короткий проход по линиям Россия → Китай → Япония.
3. Когда появится исходный OCR справочника — перегенерировать JSON новым скриптом,
   после чего тест `applies every reference correction…` сам покажет, какие
   поправки стали лишними.
