# Каркас: что можно менять свободно, а что — только осознанно

Документ для всех, кто правит **код** «Синхронии», — людей и AI-ассистентов.
Для наполнения базы фактами есть свой свод правил: [AI-CONTRIBUTING.md](./AI-CONTRIBUTING.md),
а устройство проекта целиком описано в [ARCHITECTURE.md](./ARCHITECTURE.md).

Большая часть проекта открыта для изменений. Но несколько мест — несущие стены:
неосторожная правка там ломает то, что тесты видят не всегда, или то, что у читателей
уже есть, — ссылки, сохранённые объекты, файлы. Такие места помечены в коде:

- `⚠ КАРКАС` — на этом держится работа сайта; правка требует проверки в браузере;
- `⚠ КОНТРАКТ` — на это уже опираются читатели; менять можно только с совместимостью.

Пометка ведёт сюда, в нужный раздел. Прочитайте его до правки, а не после.

---

## Три зоны

| Зона | Что в ней | Как менять |
| --- | --- | --- |
| 🟢 **Свободно** | `content/`, карточки в `src/data/items/`, страны, эпохи, маршруты, слои, заготовки конструктора; тексты интерфейса; оформление компонентов и токены темы (`styles/tokens.css`) | По правилам [AI-CONTRIBUTING.md](./AI-CONTRIBUTING.md); `npm test` проверит базу |
| 🟡 **Осторожно** | Компоненты шкалы и их CSS, `types.ts`, `vite.config.ts`, новые элементы на шкале | Проверить обе ориентации и телефон; `npm run test:e2e` |
| 🔴 **Каркас и контракты** | Разделы 1–5 ниже | Только осознанно: по рецепту из раздела и вместе с тестом |

В `types.ts` добавлять необязательные поля можно свободно; менять смысл или тип
существующего поля — значит задеть все слои сразу, это уже 🔴.

## 🔴 1. Прокрутка и виртуализация шкалы

**Где:** `components/TimelineSection.tsx` — `jumpToGroup`, `scrollItemIntoView`,
`measureGroup`, два виртуализатора; `components/TimelineRow.tsx`.

**Почему хрупко.** Шкала не пропорциональна годам и виртуализирована: в DOM только
видимые группы, размеры остальных — оценки, которые уточняются по мере измерения.
Поэтому любая прокрутка «к группе» сначала промахивается и доводится. Сверху
наложены особенности платформ: на iOS `@tanstack/virtual-core` откладывает поправки
прокрутки, пока поле движется, и применял их поверх уже точной цели (шкала уезжала
на тысячи пикселей); React 19 запрещает синхронную перерисовку во время фиксации DOM.

**Правила:**
- Любой дальний прыжок вдоль времени — только через `jumpToGroup`. Он доводит
  прокрутку, пока список не дорисован, отменяет устаревшие доводки и обходит iOS.
  Не вызывайте `scrollToIndex` или `scrollTo` поля вдоль времени напрямую.
- Группы измеряются через `measureGroup` (в микрозадаче), а не синхронно в ref.
- По виртуализатору на каждую ось; `useFlushSync` не отключать — без него
  `scrollToIndex` перестаёт попадать.
- Всё, что тянется вдоль времени, рисуется кусками в каждой группе (как полосы
  периодов в `lib/periods.ts`) или по измерениям виртуализатора — но не одним
  элементом по DOM-координатам групп, которых может не быть в DOM.
- Группы с концами видимых связей остаются смонтированными (`rangeExtractor`):
  нити меряют реальные узлы.

**Проверка:** `npm run test:e2e` — профиль iPhone гоняет iOS-путь виртуализатора;
руками — ссылка `?focus=…` в обеих ориентациях, переходы по эпохам, поле «к году».

## 🔴 2. Две ориентации шкалы

**Где:** `lib/orientation.ts`, `components/TimelineHorizontal.css`, атрибут
`data-orientation` на сцене.

**Почему хрупко.** Разметка у ориентаций одна, поворачивает её CSS. Элемент, который
сделан только для вертикальной шкалы, в горизонтальной окажется не на своём месте —
и тесты этого не заметят, пока на него не посмотрит человек.

**Правила:**
- Геометрия — в координатах «вдоль / поперёк времени» (`toScreen`, `mainOf`,
  `crossOf`), а не в `top/left`.
- Новый элемент шкалы получает правила для обеих ориентаций и для телефона
  (до 560 px), а в `README.md` — строку таблицы «Две ориентации шкалы».

**Проверка:** `lib/orientation.test.ts`, `npm run test:e2e`, скриншоты обеих ориентаций.

## 🔴 3. Содержание: сводка на шкале, полные тексты в окне

**Где:** `plugins/markdownContent.ts`, `data/contentSummary.ts`, `data/content.ts`,
`lib/sourceRule.ts`, `lib/provenance.ts`.

**Почему хрупко.** Статьи, источники и трактовки весят сотни килобайт и нужны только
в окне статьи и при экспорте. Один лишний статический импорт возвращает их в первый
экран — сайт продолжает работать, просто грузится заметно дольше.

**Правила:**
- `data/content.ts` статически импортирует только `components/modal/ModalHost.tsx`.
  Остальной код берёт сводку `item.content` или грузит базу через `import()`,
  как экспорт в `ResearchTools.tsx`. Нужен полный объект — `withContent(item)`.
- Шкале понадобилось новое поле из содержания — добавьте его в сводку
  (`summarizeMarkdownModule`), а не тяните `content.ts`.
- Сводку и полные данные строит один плагин из одних файлов; `dataIntegrity.test.ts`
  сверяет их для каждого объекта.
- `lib/sourceRule.ts` — без импортов: его загружает конфиг Vite.
- Правило верификации одно на всё — факты, связи, импорт файлов: `hasVerifiedSources`.

**Проверка:** `src/contracts.test.ts`, `dataIntegrity.test.ts`; после `npm run build` —
размер чанков `index` и `data` в выводе сборки.

## 🔴 4. Контракты с читателями: ссылки, сохранённое, файлы

Это обещания тем, кто уже пользуется сайтом. Нарушение не роняет сборку —
оно молча теряет чужие данные.

- **Ссылки** (`lib/urlState.ts`). Параметры `view`, `c`, `kind`, `q`, `key`, `bce`,
  `period`, `tag`, `z`, `o`, `layers`, `place`, `groups`, `focus`, `item`, `day`,
  `relation`, `threads`, `story`, `step` уже разосланы в закладках и конспектах.
  Новые параметры добавлять можно; переименовать старый — только продолжая читать
  прежнее имя.
- **Сохранённое в браузере** — ключи `history-line:*` в `localStorage`: `theme`,
  `show-bce`, `zoom`, `orientation`, `countries`, `added-people`, `column-groups`,
  `added-relations`, `country-sets`, `notes`, `layers`, `layer-placements`,
  `show-relations`. Ключ и форму значения не менять без переноса старого значения:
  у читателей пропадут свои объекты, связи и заметки.
- **Файлы** — `history-line/research-session@1` (экспорт сессии) и
  `history-line/custom-objects@1` (свои объекты). Новые поля — только
  необязательные. Несовместимое изменение — новая версия схемы, а импорт
  продолжает принимать `@1`.
- **id объектов.** На них ссылаются адреса, заметки, маршруты, связи и файлы
  читателей. id не переименовываются — см. [AI-CONTRIBUTING.md](./AI-CONTRIBUTING.md).

**Проверка:** `src/contracts.test.ts` — замороженная ссылка, замороженный файл
и список ключей; `lib/urlState.test.ts`, `lib/customObjects.test.ts`.

## 🔴 5. Сборка и публикация

- `base` в `vite.config.ts` — путь сайта от корня домена. Не прописывайте его
  руками: деплой берёт путь из настроек Pages (`SITE_BASE` из `actions/configure-pages`
  в `deploy.yml`) — со своим доменом это `/`, без него `/history-line/`. С неверным
  путём опубликованный сайт откроется пустым: ассеты будут искаться не там.
  Локальная сборка, CI и e2e-тесты работают с путём по умолчанию `/history-line/`.
- Группы чанков `vendor` и `data` (`isTimelineData`): `data/content.ts` исключён
  из `data` намеренно — см. раздел 3.
- `src/data/items/reference.json` генерирует `scripts/import_history_reference.py`;
  руками его не правят, а перегенерируют.
- Код, который загружает конфиг Vite (`plugins/`), импортирует из `src/` только
  модули без собственных импортов и с расширением `.ts`.

## Если каркас всё-таки нужно изменить

Так бывает, и это нормально, — если делать это осознанно:

1. Прочитайте раздел и найдите тест, который охраняет правило.
2. Меняйте тест вместе с кодом, в том же коммите, и объясните в сообщении коммита,
   почему старое правило больше не нужно и что стало с совместимостью.
3. Прогоните всё: `npm run lint && npm test && npm run build && npm run test:e2e`.
4. Посмотрите глазами обе ориентации, тёмную тему и телефон.
5. Поправьте этот документ.

**Никогда:** не удаляйте и не пропускайте тест, чтобы CI стал зелёным, и не
отключайте проверки в CI. Упавший тест здесь почти всегда означает, что сломано
что-то настоящее.
