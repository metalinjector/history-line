# Качество и происхождение данных

History Line различает наличие текста и подтверждённость утверждения. Подробное
объяснение без опубликованных источников остаётся полезной редакционной гипотезой,
но не должно выглядеть в интерфейсе как верифицированный факт.

## Контракт верификации

Объект или связь считается верифицированной, если одновременно выполнены условия:

1. опубликованы как минимум два независимых источника;
2. у каждого источника есть понятное библиографическое название; URL обязателен
   для новых пользовательских связей, а источник базы может быть описан
   без публичного URL — см. [«Что такое источник без URL»](#что-такое-источник-без-url);
3. хотя бы один источник — академическая публикация, архив либо профильное учреждение,
   а не энциклопедия;
4. связь дополнительно имеет `verification: 'verified'` — статус нельзя получить
   случайно одним только добавлением URL.

Связи старой базы без явного статуса считаются `draft`. В интерфейсе они рисуются
более лёгким пунктиром, а модальное окно прямо предупреждает о редакционном статусе.
Это не утверждение, что связь неверна; это честная граница того, что репозиторий
может доказать прямо сейчас.

## Автоматические проверки

Команда `npm run validate:data` проверяет:

- глобальную уникальность идентификаторов объектов, слоёв и связей;
- допустимость стран и календарных полей;
- непустые обязательные поля;
- отсутствие связей с несуществующими концами;
- полный комплект источников у каждой записи, заявленной как проверенная;
- измеримый отчёт о покрытии источниками в логе CI.

Проверка входит в `npm test`, а GitHub Actions запускает установку из lock-файла,
линтер, все тесты и production build на каждом pull request.

## Что такое источник без URL

Ссылка ставится только тогда, когда её действительно открывали. Источник без `url` —
не заготовка и не полуфабрикат, а обычная библиографическая запись: так цитируются
публикации документов, летописи, монографии и архивные фонды, у которых нет
устойчивого адреса в сети. Выдуманная или протухшая ссылка хуже её отсутствия:
она создаёт видимость проверки там, где проверки не было.

Отсюда практическое следствие для того, кто наполняет базу: **добавляйте `url`
в отдельном проходе, когда есть доступ в сеть и возможность открыть каждую ссылку.**
Контракт верификации на это не завязан — он считает названия и типы, а не адреса.

## Текущий редакционный долг

Источники проставлены всем объектам основной базы и всех слоёв. У связей библиография
своя: она должна подтверждать именно причинное утверждение, а не события по краям,
поэтому часть связей осознанно осталась в статусе `draft`.

Draft — это не «связь неверна». Это либо длинная интерпретационная цепочка
(заграничные походы 1813–1814 годов → отмена крепостного права в 1861-м), либо
синхронность без влияния (полёт Гагарина и Берлинская стена в одном 1961 году).
Такие связи полезны читателю и остаются на шкале, но рисуются более лёгким пунктиром
и честно помечаются в окне.

Динамические числа печатаются тестом `publishes a measurable provenance baseline`;
их следует использовать как baseline и повышать отдельными небольшими PR.

Незакрытый долг, по убыванию важности:

1. **URL у источников.** Проставлены только у части записей — см. раздел выше.
2. **Пять draft-связей.** Либо найти источник именно на механизм влияния,
   либо переформулировать связь так, чтобы она не заявляла причинность.
3. **Трактовки.** `viewpoints` есть у пяти объектов; расхождения историографий
   наверняка есть и у других — их нужно находить и оформлять.

Рекомендуемый порядок работы со старой связью:

1. проверить формулировку и направление причинности;
2. добавить два независимых источника именно для связи, а не только для событий;
3. при необходимости переписать `detail`, отделив факт от интерпретации;
4. выставить `verification: 'verified'`;
5. убедиться, что `npm run validate:data` проходит локально и в CI.
