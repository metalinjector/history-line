# Устройство проекта и точки расширения

Документ отвечает на один вопрос: **что нужно тронуть, чтобы добавить новую
возможность** — и где проходят границы, за которые лучше не заходить.

Для наполнения базы фактами есть отдельный свод правил:
[AI-CONTRIBUTING.md](./AI-CONTRIBUTING.md).

---

## 1. Три слоя и правило зависимостей

```text
content/  редакционное наполнение  → обычные Markdown-файлы, кода не содержат
data/     что мы знаем о мире      → не знает ничего об интерфейсе
lib/      что мы с этим делаем     → знает data, не знает React-разметку
components/ как это выглядит       → знает lib и data, но не содержит логики
```

Зависимости идут только вниз. Практическое следствие: заменить `data/` на загрузку
из JSON, CMS или API можно, не открывая ни одного компонента, — нужен лишь модуль,
отдающий те же типы.

Всё состояние собрано в одном хуке `lib/useTimelineState.ts`. Компоненты получают
готовые данные и действия, поэтому любой экран можно переписать, не трогая логику.

## 2. Ключевые абстракции

### 2.1. Дорожка (`Track`)

Самая важная обобщённая сущность. Дорожка — это одна линия шкалы внутри колонки
(в горизонтальной раскладке — внутри полосы). Дорожкой может быть **страна** или **наложенный слой**:

```ts
type Track = {
  id: string;            // 'country:germany' | 'layer:einstein'
  label; short; color; colorInk;
  kind: 'country' | 'layer';
  countryId?: CountryId;
  layerId?: string;
};
```

Колонка держит массив дорожек и ничего не знает о том, что именно в ней лежит.
Из этого бесплатно работают три разных сценария:

| Сценарий | Дорожки в колонке |
| --- | --- |
| Обычная страна | одна дорожка страны |
| Две страны в одной колонке | две дорожки стран |
| Страна и её предшественник | дорожка страны + унаследованная дорожка |
| Слой поверх страны | дорожка страны + дорожка слоя |
| Слой в своей колонке | одна дорожка слоя |

Унаследованная дорожка помечена `inherited: true`. Пометка нужна там, где важно
отличить её от ручного объединения: разъединить можно только то, что читатель
соединил сам, а предшественник появляется и исчезает вместе со своим наследником.

Позиции узлов считаются формулой от `--rail-center` и `--rail-gap`, поэтому колонка
на три и более дорожек не требует новых правил — только смены предела `MAX_PER_COLUMN`.

### 2.2. Объект хронологии (`TimelineItem`)

Единая структура для всего, что стоит на шкале: событие, деятель, элемент слоя,
объект, добавленный пользователем. Отличаются только служебными полями
(`layerId`, `custom`), а вся механика — фильтры, группировка, связи, окна — общая.

### 2.3. Уровень детализации (`Granularity`)

Группировка вынесена в функцию с параметром `'year' | 'month' | 'day'`.
Ключи групп (`'1789'`, `'1789-07'`, `'1789-07-14'`) и сортировка через `timeKey`
рассчитаны на все три уровня. Добавить «недели» или «часы» — значит добавить
шаг в `GRANULARITY_STEPS` и ветку в `groupKeyOf`.

### 2.4. Ориентация (`Orientation`)

`'vertical' | 'horizontal'` — свойство раскладки, а не данных. `buildGroups`, колонки,
дорожки, фильтры, связи и разметка группы (`TimelineRow`) от ориентации не зависят;
различаются только:

| Где | Что меняется |
| --- | --- |
| `TimelineHorizontal.css` | поворот раскладки поверх той же разметки: полосы, линейка лет, узлы над карточками |
| `TimelineSection.tsx` | ось виртуализации, отступ списка, «уместить», колесо мыши, стрелки, якорь при повороте |
| `lib/orientation.ts` | геометрия штриховых линий и нитей, шаги навигации, слова «колонка / полоса» |
| `TimelineOverlay.tsx` | какая координата узла — дата (через `lib/orientation.ts`) |

Геометрия пишется в координатах «вдоль времени» (main) и «поперёк» (cross),
а в экранные x/y переводится одной функцией `toScreen`. Поэтому новая фигура
поверх шкалы, написанная в этих координатах, сразу работает в обеих ориентациях.

У каждой оси свой экземпляр виртуализатора (`enabled` только у текущего): размеры,
измеренные по одной оси, для другой бессмысленны. Перед поворотом запоминается якорь —
выбранная карточка, если она на экране, иначе первая видимая группа, — и после
поворота шкала открывается на нём.

### 2.5. Содержание отдельно от кода

Статьи, источники и трактовки лежат не в TypeScript, а в `content/items/<страна>/<id>.md`
и `content/layers/<слой>/<id>.md`: шапка с `sources` и `viewpoints`, ниже — статья.
Причин три:

1. **Наполняет базу не программист.** Создать текстовый файл проще, чем не сломать
   многострочный шаблонный литерал в чужом модуле.
2. **Правки видны в диффе построчно.** Изменение одной статьи не трогает файл на 650 строк.
3. **Формат переживёт этот интерфейс.** Markdown с YAML-шапкой читают Obsidian, любой
   генератор статики и следующая версия проекта.

Front-matter разбирает плагин сборки `plugins/markdownContent.ts` и отдаёт готовый объект,
поэтому YAML-парсер остаётся devDependency и в бандл не попадает. Каждый файл читается
в двух видах:

- **Сводка** (`*.md?summary` → `data/contentSummary.ts`): есть ли статья, проверен ли факт
  по правилу `hasVerifiedSources`, сколько трактовок. Она входит в основной бандл
  и лежит в поле `item.content`: по ней карточка ставит значок ⚖, а сводка редакции
  считает покрытие (`isItemVerified` в `lib/provenance.ts`).
- **Полные данные** (`*.md` → `data/content.ts`): статьи, источники, трактовки.
  Весят в разы больше и нужны только в модальном окне и при экспорте, поэтому
  `content.ts` импортируют лишь ленивый `ModalHost` и `ResearchTools` (через `import()`).
  `withContent(item)` возвращает объект с подмешанными `body`, `sources`, `viewpoints`.

Сводку и полные данные строит один плагин из одних файлов, а `dataIntegrity.test.ts`
сверяет их для каждого объекта, поэтому разойтись они не могут.

Следующий шаг, если он понадобится: заменить `import.meta.glob` на запрос к API,
не трогая ничего, кроме `data/content.ts` и `data/contentSummary.ts`.

## 3. Как добавить возможность

### 3.1. Новая страна

`data/items/<страна>.ts` + строка в `data/timelineItems.ts` + запись
в `data/countries.ts` + папка `content/items/<страна>/`. Больше ничего: ширина таблицы,
переключатели, кольца дат, цвета и раскладка считаются от справочника.

### 3.2. Новый слой

Одна запись в `data/layers.ts` с полями `category` (`person` | `event`)
и `defaultPlacement`, плюс файлы содержания в `content/layers/<слой>/`.
Меню разложит слой в нужный раздел, размещение и перетаскивание заработают сами.
Предел одновременных слоёв — константа `MAX_ACTIVE_LAYERS`;
ни `applyLayers`, ни `materializeLayerItems`, ни раскладка колонок на это число
не завязаны, поэтому поднять лимит — значит поменять одно число.

### 3.3. Новый способ нарезать время

`data/periods.ts` — единственное место, где живёт понятие «выбранный отрезок».
Эпохи и интервалы по 300 лет уже сосуществуют там как два варианта одного типа
`Period`. Добавить третий способ (например, «по векам» или «по правлениям») —
значит добавить вариант в `Period`, ветку в `periodRange`, `encodePeriod`
и `decodePeriod` и группу в выпадающем списке. Фильтрация, подсчёт объектов
и ссылка на текущий вид продолжат работать: они знают только про `Period`.

### 3.4. Новая линия-предшественник

Одна строка в таблице `predecessors` в `data/countries.ts`: `italy: ['ancient-rome']`.
Дальше всё считается само — дорожка в колонке, расширение фильтра, счётчик на чипе.

Два правила, которые проверяет `data/columns.test.ts`:

1. **У предшественника ровно один наследник.** Иначе один объект попал бы в две колонки.
2. **Предшественник — историческая линия** (`kind: 'historical'`), а не современная страна.

Если читатель выбрал древнюю линию отдельной колонкой, наследник её не забирает:
`impliedAncestors` пропускает то, что уже выбрано.

### 3.5. Новый готовый набор стран

Одна запись в `data/countrySets.ts`. Встроенные и пользовательские наборы имеют
одинаковую форму `CountrySet`, поэтому UI их не различает нигде, кроме права
на удаление. Свои наборы хранятся в `localStorage` под ключом `country-sets`;
предел — константа `MAX_USER_SETS`.

Кнопки «показать все страны» нет сознательно: каталог перевалил за сотню линий,
и одновременный показ всех даёт нечитаемую таблицу. Наборы — замена этой кнопки.

### 3.6. Новый вид связи

Добавить значение в `Relation['kind']`, цвет в `.thread[data-kind=…]`
и подпись в `kindLabels`. Геометрия нитей от вида не зависит.

### 3.7. Новый блок в окне объекта

Компонент в `components/modal/` и одна строка в `ItemModal`. Так уже сделаны
трактовки (`Viewpoints`), источники и редактор заметок (`NoteEditor`) — каждый
блок самостоятелен и ничего не знает о соседях.

### 3.8. Новый элемент раскладки шкалы

Разметка пишется один раз — в `TimelineRow`, `TimelineHeader` или `TimelineSection`.
Положение задаётся CSS: в `TimelineSection.css` для вертикальной шкалы и переопределением
в `TimelineHorizontal.css` под `[data-orientation='horizontal']`. Если элемент рисуется
в SVG-слое, его координаты считаются через `toScreen`, `mainOf` и `crossOf`
из `lib/orientation.ts`. Подписи, где встречается слово «колонка», берут его из
`laneWords(orientation)`: в горизонтальной шкале это «полоса».

### 3.9. Новый инструмент Markdown

`MarkdownView` — единственное место, где разбирается Markdown. Он используется
и статьями, и связями, и заметками, поэтому добавленный плагин появляется
везде сразу. Панель инструментов редактора описана массивом `tools`:
кнопка — это запись с функцией, которая оборачивает выделение.

## 4. Что уже готово к заявленным расширениям

### 4.1. Конструктор событий пользователем

**Готово:**

- форма добавления объекта с выбором страны, года, типа, тегов;
- автоподбор исторических связей (`lib/suggestRelations.ts`) прямо при вводе;
- пользовательские объекты и связи живут в состоянии наравне с базовыми
  и проходят те же фильтры, попадают в те же окна и нити;
- всё сохраняется между сессиями.

**Чего не хватает для полноценного конструктора:**

| Пробел | Что нужно | Сложность |
| --- | --- | --- |
| Нет полей месяца, дня, `endYear`, `importance` | Расширить форму — модель уже всё поддерживает | низкая |
| Нельзя отредактировать уже добавленный объект | Форма в режиме правки + `updatePerson` в состоянии | низкая |
| Нельзя написать статью и указать источники | Подключить `NoteEditor` как редактор `body` и список источников | средняя |
| Пользовательские объекты нельзя выгрузить | Экспорт в JSON по форме `TimelineItem[]` | низкая |

Ни один из пробелов не требует менять модель или раскладку — только форму.

### 4.2. Редактирование в модалках

**Готово:** редактор заметок с панелью инструментов Markdown, переключением
«правка / просмотр», поддержкой ссылок `[[id]]` и формул, сохранением в браузере.
Заметки намеренно отделены от базы фактов: это пометки читателя, а не сведения,
прошедшие проверку источниками.

**Чтобы превратить его в редактор самой базы**, нужно:

1. Переиспользовать `NoteEditor` для поля `body` — он для этого и написан
   без привязки к заметкам.
2. Добавить редактирование `sources` и `viewpoints` (списки с формой).
3. Решить вопрос хранения: сейчас правки живут в `localStorage`. Для общей базы
   нужен либо экспорт патча в JSON с ручным ревью, либо бэкенд.

Третий пункт — единственное настоящее архитектурное решение из оставшихся,
и его стоит принимать осознанно: правка фактов без проверки источниками
противоречит правилу из [AI-CONTRIBUTING.md](./AI-CONTRIBUTING.md).

## 5. Известные ограничения

| Ограничение | Почему так | Когда станет проблемой |
| --- | --- | --- |
| Слои материализуются целиком | Слой — это десяток объектов | при слоях в сотни событий |
| Состояние в `localStorage` | Нет бэкенда | при переносе между устройствами |
| Конец периода за пределами отрисованных групп | Линия к дате окончания ставится по ближайшим отрисованным группам | когда периоды начнут рисоваться полосами — брать позиции групп из измерений виртуализатора |
| Пустые линии ужимаются только в горизонтальной шкале | В вертикальной пустая колонка дешевле: ширины обычно хватает | если колонок станет много — то же правило для `--cols` |
| Нити связей считаются по DOM | Точность важнее скорости, связей десятки | при сотнях связей — считать по модели, а не по узлам |

## 6. Карта файлов

```text
content/
  items/<страна>/<id>.md      источники, трактовки и статья — по файлу на объект
  layers/<слой>/<id>.md       то же самое для объектов слоёв
plugins/
  markdownContent.ts          разбор front-matter на этапе сборки
src/
  types.ts                    вся доменная модель, единственный источник истины о форме данных
  data/
    countries.ts              справочник стран
    columns.ts                раскладка колонок, объединение стран, поиск колонки объекта
    layers.ts                 слои, их категории и предел одновременных
    eras.ts                   эпохи
    periods.ts                отрезки времени: эпохи и интервалы по 300 лет
    countrySets.ts            наборы стран
    timelineItems.ts          сборка базы: карточки + сводка редакционной базы
    items/*.ts                карточки по странам; reference.json — импорт справочника
    contentSummary.ts         сводка content/ для шкалы (запрос ?summary)
    content.ts                статьи, источники, трактовки — только для окна и экспорта
    relations.ts              связи между объектами
    suggestedPeople.ts        заготовки для конструктора
  lib/
    timeline.ts               фильтрация, группировка, уровни детализации
    orientation.ts            ось времени: геометрия, навигация, словарь «колонка/полоса»
    useWheelAlongTime.ts      колесо мыши листает время в горизонтальной шкале
    layers.ts                 размещение слоёв, материализация их объектов
    markdown.ts               сборка статьи, ссылки [[id]]
    suggestRelations.ts       подбор кандидатов на связь
    format.ts                 даты, склонения, ключ сортировки
    useTimelineState.ts       всё состояние приложения
    usePanning.ts             перетаскивание поля
    usePersistentState.ts     сохранение между сессиями
  components/
    TimelineSection.tsx       сборка экрана хронологии
    TimelineControls.tsx      панель: на виду тип, поиск и период; остальное в «Настройках»
    TimelineOverlay.tsx       SVG-слой: штриховые линии и нити
    TimelineHorizontal.css    горизонтальная раскладка поверх той же разметки
    LayerMenu.tsx             меню слоёв и перетаскивание
    modal/                    окна и вся работа с Markdown
```
